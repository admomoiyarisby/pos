Skenario 03 — SCM Procurement

Alur procure-to-pay baru (FSM, ADR 0002)
Bahasa Indonesia · gaya Tufte · sumber: scm-fsm.ts

← Kembali ke indeks

Ini procurement pusat (bahan dari supplier ke Central Kitchen). Seluruh alur dikendalikan oleh tabel transisi di scm-fsm.ts:91, dan transition() (scm-fsm.ts:244) adalah satu-satunya pemutar status — berjalan dalam satu tx terkunci baris. Fokus review: actor per transisi, efek per status, dan arah reversal saat cancel.

Tabel status & transisi (spesifikasi)

Status Event → next Actor Efek penting
Draft submit→Pending · cancel→Cancelled BA, SA —
Pending open-review→UnderReview · withdraw→Draft · cancel AP/SA review —
UnderReview reject→Rejected · accept-and-ship→InTransit · cancel AP/SA copyReadyToPicked + writeInTransitInventory
InTransit mark-delivered→Delivered · cancel BA/SA moveStockToPendingReview
Delivered open-receive→ReviewingSJ · cancel BA/SA reversePendingReviewOnCancel
ReviewingSJ finish-receive→WaitingForPayment · cancel BA/SA setReceived + writeReceivedStock + writeRejectedWaste + generateInvoiceSnapshot
WaitingForPayment mark-paid→Finished · cancel AP/SA markInvoicePaid
Rejected / Finished / Cancelled terminal — tidak ada transisi keluar
Invarian — super_admin di mana saja super_admin diizinkan pada setiap transisi (override darurat). Ini tidak tertulis di tabel tapi ditambahkan saat dispatch. Saat review, sadari bahwa super_admin bisa lewati review area manager.

A. Buat procurement (Draft)

Otorisasi createProcurement (scm-queries.ts:36) butuh branch_admin atau super_admin. Bukan admin_pusat di sini (beda dari Mutasi!). Kode dokumen Kode otomatis PR/<branch>/ddmmyy/serial via generateDocumentCode("PR", branch.code) (scm-queries.ts:47).
  1. Di UI procurement, BA isi items (ingredientId + quantity) → createProcurement (scm-queries.ts:22).
  2. Server generate kode, insert scmProcurements status Draft, insert scmProcurementItems dengan unitPrice di-snapshot dari ingredients.averageCost (scm-queries.ts:64-84).
  3. Tulis audit create (fromState=null → toState=Draft) (scm-queries.ts:88).
Jebakan — unitPrice snapshot Harga di-snapshot saat create. Bila averageCost bahan berubah nanti, unitPrice di item procurement tidak ikut berubah (scm-queries.ts:82). Saat review, pastikan invoice memakai snapshot ini (bukan live cost) — dan itu memang yang diinginkan.

B. Submit → Pending → review

  1. BA klik submit → transition(id, "submit", …) → Draft→Pending. Actor BA/SA. Tanpa efek stok.
  2. Admin Pusat/SA klik "open review" → event open-review → Pending→UnderReview, catat reviewingById (scm-fsm.ts:274).

C. Accept & ship (UnderReview → InTransit)

  1. AP/SA klik "accept and ship" → accept-and-ship → UnderReview→InTransit.
  2. Efek (scm-fsm.ts:115-118): copyReadyToPicked + writeInTransitInventory (stok dipindah ke posisi in-transit). Berjalan dalam tx yang sama dengan perubahan status.
  3. Edit item (CA): updateItem dengan caDecision/readyQuantity hanya diizinkan saat UnderReview (scm-fsm.ts:408).
Invarian — edit item state-gated updateItem (scm-fsm.ts:385) memaksa: field CA hanya di UnderReview; field BA (received/rejected) hanya di Delivered/ReviewingSJ; field quantity hanya di Draft. UI harus menyembunyikan field di luar status yang benar.

D. Terima & invoice (Delivered → WaitingForPayment)

  1. BA klik "mark delivered" → mark-delivered → InTransit→Delivered (efek moveStockToPendingReview).
  2. BA klik "open receive" → open-receive → Delivered→ReviewingSJ (catat receivingById).
  3. BA isi received/rejected per item → updateItem (BA fields, status ReviewingSJ/Delivered).
  4. BA klik "finish receive" → finish-receive → ReviewingSJ→WaitingForPayment. Efek (scm-fsm.ts:146-156): setReceivedQuantities + writeReceivedStock + writeRejectedWaste + generateInvoiceSnapshot.

E. Bayar (WaitingForPayment → Finished)

  1. AP/SA klik "mark paid" → mark-paid → WaitingForPayment→Finished. Efek markInvoicePaid.
  2. Status terminal Finished — tidak ada transisi keluar.

F. Cancel di setiap titik (paling kritis)

  1. Setiap status punya event cancel, tapi efek reversal berbeda tergantung titik:
    • Draft/Pending/UnderReview (belum stok bergerak): noopOnCancel — hanya ubah status.
    • InTransit: reverseInTransitOnCancel — kembalikan stok in-transit.
    • Delivered / ReviewingSJ / WaitingForPayment: reversePendingReviewOnCancel.
  2. Semua cancel menulis audit fromState→Cancelled + cancelledBy/cancelledAt/cancellationReason (scm-fsm.ts:293-297).
Jebakan — arah reversal cancel Pastikan tiap reverse* tepat membatalkan efek forward untuk titik itu. Bila salah pasang (mis. InTransit dipakai noopOnCancel), stok yang sudah dipindah ke in-transit akan tertinggal dan merusak saldo. Ini celah finansial diam.

G. Mekanisme transition() (inti keamanan)

  1. transition() (scm-fsm.ts:244) membuka tx, SELECT … FOR UPDATE pada procurement (scm-fsm.ts:252-256).
  2. Cari rule di tabel; bila tak ada → InvalidTransitionError; bila actor tak diizinkan → UnauthorizedError (scm-fsm.ts:260-265).
  3. Jalankan semua efek dalam tx, update status + audit + notifikasi (scm-fsm.ts:300-341). Semua commit bersama atau rollback bersama.
Checklist akhir scenario 03
  • Self-check untuk FSM ini tidak ada (hanya Mutasi yang punya). Pertimbangkan menulis scm-fsm.selfcheck.ts paralel.
  • Setiap (status, event) punya actor & efek yang sesuai spec.
  • Cancel reversal arahnya benar per titik.
  • Edit item state-gated; UI menyembunyikan field di luar status.
  • super_admin bypass review — disengaja?
