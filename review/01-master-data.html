Skenario 01 — Master Data

Tambah bahan baku → buat resep → pasang modifier & visibility
Bahasa Indonesia · gaya Tufte · nomor baris dari sumber

← Kembali ke indeks

Skenario ini menelusuri rantai master data paling dasar: kita buat satu bahan baku, lalu resep yang memakai bahan itu, lalu grup modifier dan aturan visibility cabang. Fokus review: siapa yang berhak, validasi Zod, dan — yang paling penting — kapan HPP (totalCogs) benar-benar terhitung.

A. Tambah bahan baku

Otorisasi Semua mutasi master bahan hanya untuk super_admin, admin_pusat, central_kitchen (ingredients.ts:80). Bukan branch_admin dan bukan area_manager. UI src/routes/_layout/ingredients/index.tsx membungkus tombol "Tambah Bahan" (baris ~201) dalam RoleGuard dengan role yang sama.
  1. Buka /ingredients. Klik Tambah Bahan → modal form terbuka (ingredients/index.tsx:201,208).
  2. Isi field berikut (divalidasi oleh ingredientInput Zod di ingredients.ts:11):
    Field Aturan Zod Catatan
    code string 1–30, wajib Unik (constraint DB)
    name string 1–100, wajib
    category enum Fresh|Dry|Packaging
    skuType enum RM|SFG|FG RM=bahan mentah
    purchaseUnit / stockUnit string wajib Satuan beli vs satuan stok
    conversionFactor int ≥ 1 1 beli = N stok
    averageCost int ≥ 0 Ini HPP per unit stok
    plannedCost int ≥ 0, opsional
    rop / roq int ≥ 0 (default 0) Reorder point/qty
    moq int ≥ 1 (default 1) Kelipatan saat PR
    countable boolean (default true)
  3. Submit → createIngredient (ingredients.ts:77). Server: requireRole(...), lalu ingredientInput.parse(data), lalu insert + audit log CREATE.
  4. Konfirmasi toast "Bahan baku berhasil ditambahkan" dan baris baru muncul di tabel.
Jebakan — tidak ada stok otomatis createIngredient hanya menyisipkan baris ingredients. Tidak ada baris inventory yang dibuat. Artinya stok awal bahan = 0 di semua cabang sampai ada pengiriman/opname yang menambahnya. Saat review, pastikan UI tidak memberi kesan stok sudah ada.
Jebakan — hapus (soft delete) deleteIngredient (ingredients.ts:144) hanya soft-delete (status→Inactive) kecuali hardDelete:true. Hard delete diblokir jika bahan masih dirujuk di recipeIngredients (ingredients.ts:162). Periksa apakah UI menawarkan hard delete dan apakah guard ini cukup.

B. Ubah HPP bahan → roll-up ke resep

  1. Buka /ingredients/$ingId (detail). Klik Edit ($ingId.tsx:78).
  2. Ubah averageCost (field "HPP (Rp)" di $ingId.tsx:167), lalu Simpan.
  3. Submit → updateIngredient (ingredients.ts:101). Server cek: jika "averageCost" in updates (ingredients.ts:119), panggil recalculateRecipeCostsForIngredient(id).
  4. cost-rollup.ts:9 mencari semua recipeIngredients yang memakai bahan ini, lalu per resep menjumlahkan averageCost × quantity dan menulis recipes.totalCogs (cost-rollup.ts:25-38).
Invarian — roll-up hanya level-1 recalculateRecipeCosts (cost-rollup.ts:25) HANYA menjumlahkan recipeIngredients. Ia tidak menelusuri recipeChildRecipes (sub-resep). Jika resep induk memakai sub-resep, HPP sub-resep tidak masuk ke totalCogs induk. Saat review, pastikan ini memang disengaja atau ada roll-up rekursif di tempat lain.

C. Buat resep yang memakai bahan tadi

Otorisasi createRecipe butuh super_admin atau admin_pusat (recipes.ts:231) — beda dari bahan yang mengizinkan central_kitchen. Perhatikan ketidakselarasan ini. Skema input recipeInput (recipes.ts:32): ingredients tiap item butuh quantity: int ≥ 1 (recipes.ts:24).
  1. Buka /recipes, klik tambah resep (form wizard bersama).
  2. Isi recipeInput (recipes.ts:32):
    • code, name, category (makanan|minuman|snack|add_ons|paket_bundle), basePrice (int ≥ 0).
    • isSubRecipe (default false), isBOGO (default false), isStaffMeal tidak di input ini (di-set via update/flag lain).
    • brandIds[] — link ke brand.
    • ingredients[] — pasang bahan dari langkah A dengan quantity (int ≥ 1).
    • childRecipes[] (opsional) — sub-resep bersarang.
    • modifierGroupIds[] (opsional) — grup modifier.
    • branchIds[] (opsional, nullable) — visibility cabang.
  3. Submit → createRecipe (recipes.ts:228). Urutan tulis: recipes → recipeBrands → recipeIngredients → recipeChildRecipes → recipeModifierGroups → recipeBranches (recipes.ts:234-293).
Jebakan — totalCogs = 0 saat create createRecipe tidak memanggil roll-up HPP. Kolom totalCogs resep baru mengambil default skema = 0 (schema.ts: totalCogs: integer ... default 0). HPP baru terhitung saat (a) bahan diubah HPP-nya nanti, atau (b) recalculateAllRecipeCosts (recipes.ts:408, butuh super_admin) dijalankan. Saat review, cek apakah UI menampilkan "HPP Rp 0" misleadingly setelah create.
Jebakan — semantic visibility cabang Jika branchIds diisi → resep HANYA muncul di cabang tersebut (recipeBranches ada). Jika branchIds kosong/null → tidak ada baris recipeBranches → "terlihat di semua cabang" (recipes.ts:290, dan query getPosMenu di pos.ts:50-55). Kebalikannya mudah terbolak-balik: "kosong = semua" bukan "kosong = tidak ada".

D. Grup modifier & eksklusi (opsional tapi penting)

  1. Buka /modifier-groups. Buat grup (mis. "Level Gula") dengan minSelection/maxSelection.
  2. Tambah modifiers ke grup (mis. "Tanpa Gula", harga 0, isExclusion bila ini pengurang).
  3. Pasang grup ke resep via modifierGroupIds (langkah C) — link disimpan di recipeModifierGroups.
  4. Untuk eksklusi bahan (mis. "tanpa bawang"), entri recipeModifierExclusions / modifierIngredients akan dipakai saat order oleh resolveNewItemIngredients — lihat Skenario 02.

Kenapa ini penting untuk stok

Modifier & eksklusi mengubah BOM per-item saat order. Jika eksklusi tidak dikelola benar, stok bahan akan terpotong padahal seharusnya di-restore. Ini titik paling sering salah di Skenario 02.

E. Verifikasi HPP & lintasan

  1. Buka detail resep /recipes/$recipeId (getRecipeDetail, recipes.ts:148) — periksa totalCogs sudah ≠ 0 setelah roll-up.
  2. Bila perlu, jalankan recalculateAllRecipeCosts (recipes.ts:408, super_admin) untuk hitung ulang semua.
  3. Lacak di system_logs / audit: "Create Ingredient", "Update Ingredient", "Create Recipe" — pastikan ada jejak audit untuk tiap langkah.
Checklist akhir scenario 01
  • Role guard benar di tiap server fn (bahan vs resep beda izin).
  • Validasi Zod sesuai (int, enum, min).
  • totalCogs resep tidak dibiarkan 0 setelah alur normal.
  • Soft-delete bahan aman terhadap resep yang merujuk.
  • Visibility cabang: "kosong = semua cabang".
