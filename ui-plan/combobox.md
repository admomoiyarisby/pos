# Combobox Implementation Plan

> **Goal:** Replace long, unsearchable `<select>` dropdowns with searchable comboboxes across high-traffic SCM and inventory forms.
> **Do not implement yet.** This document is the instruction set for the worker agent.

---

## 1. Problem Statement

Several forms in the app use native `<select>` elements to pick items from lists that can grow to 50–100+ entries:

- **Purchase Requisition** — choosing an ingredient from the master list while viewing live stock, MOQ, and ROP indicators.
- **Waste Entry** — choosing an ingredient.
- **Yield Tracking** — choosing source RM and target SFG/FG ingredients.
- **Stock Transfer** — choosing an ingredient.
- **Recipe Bundling** — choosing child recipes from the full recipe list.

As the ingredient/recipe catalog grows, scrolling a `<select>` becomes unusable. Users need **type-ahead search** so they can type "beras" and immediately find "Beras Premium" without scrolling.

## 3. Component Strategy

### 3.1 Dependencies to Install

The project already uses shadcn/ui (`components.json` exists, `style: "new-york"`). The canonical shadcn/ui combobox pattern is built on top of `cmdk` + Radix Popover, but the easiest way to get it is through the shadcn CLI.

Run the following commands to install the required shadcn/ui components and their dependencies:

```bash
npx shadcn add command combobox
```

This will:

1. Install `cmdk` and `@radix-ui/react-popover` (if missing).
2. Create `src/components/ui/command.tsx` — the `Command` primitive wrapper (search input, list, item, empty state, group, separator).
3. Create `src/components/ui/combobox.tsx` — the canonical shadcn/ui combobox pattern.

> Verify that `cmdk` and `@radix-ui/react-popover` are not already in `package.json` before installing. Do **not** use `pnpm`/`npm` directly — use `npx shadcn add` per the project's Vite+ workflow.

### 3.2 Reusable `Combobox` Component

The shadcn CLI will generate a `combobox.tsx` file that follows the standard shadcn/ui pattern. This component is already a **controlled, headless-ish wrapper** built on top of `cmdk` + Radix Popover, styled consistently with the existing `select.tsx` component (same border, radius, focus ring, shadow, animation tokens).

**Props interface (generated by shadcn):**

```ts
interface ComboboxOption {
  value: string; // the ID / form value
  label: string; // primary display text
  keywords?: string[]; // extra search terms (e.g. ingredient code)
  disabled?: boolean;
}

interface ComboboxProps {
  options: ComboboxOption[];
  value?: string;
  onChange: (value: string) => void;
  placeholder?: string;
  searchPlaceholder?: string;
  emptyText?: string;
  disabled?: boolean;
  // Optional: render custom content per option
  renderOption?: (option: ComboboxOption) => React.ReactNode;
  // Optional: render custom display for the trigger when an item is selected
  renderValue?: (option: ComboboxOption) => React.ReactNode;
}
```

**UX requirements:**

- Trigger looks like the existing `SelectTrigger` (bordered input, chevron down icon).
- Clicking trigger opens a **Popover** (not a native select dropdown).
- Popover contains a `Command` (cmdk) root with:
  - A search input at the top (`CommandInput`).
  - A scrollable list (`CommandList` > `CommandGroup` > `CommandItem`).
- Keyboard navigation: ↑/↓ to move, Enter to select, Escape to close.
- Click outside closes the popover.
- When `value` is set, the trigger shows the selected label (or custom `renderValue`).
- When `value` is empty, show `placeholder`.
- If no results match, show `emptyText` (default: "Tidak ada hasil").

**Styling requirements (match existing design system):**

- Trigger: `h-9`, `rounded-md`, `border border-input`, `bg-background`, `px-3`, `text-sm`, same focus ring as `SelectTrigger`.
- Popover content: `z-50`, `rounded-md`, `border`, `bg-popover`, `shadow-md`, `max-h-72`, `overflow-y-auto`.
- Active/hovered item: `bg-accent`, `text-accent-foreground`.
- Selected item: show a check icon on the right (same as `SelectItem`).
- Search input inside popover: `h-8`, borderless or subtle bottom border, placeholder text muted.

### 3.3 Why Not Enhance the Existing `<Select>`?

The existing `select.tsx` is built on `@radix-ui/react-select`. Radix Select does **not** support an internal search/filter input inside the dropdown viewport — it is designed for native-style keyboard navigation (type first letter to jump). A true combobox needs a dedicated search box, which is why `cmdk` + `Popover` is the standard shadcn/ui pattern.

## 4. Page-by-Page Implementation Spec

### 4.1 Purchase Requisitions (`src/routes/_layout/purchase-requisitions/index.tsx`)

**Current code block to replace:**
The `<select id="pr-ingredient">` inside the Create PR modal (around line 295 in the current file).

**Current option rendering logic:**

```tsx
ingredients.map(function (i) {
  var invItem = branchInventory.find(...);
  var invQty = invItem ? invItem.quantity : 0;
  var isLow = i.rop > 0 && invQty <= i.rop;
  return (
    <option key={i.id} value={i.id}>
      {i.name} ({i.stockUnit}) — Stok: {invQty} {i.moq > 1 ? `(MOQ: ${i.moq})` : ""} {isLow ? "⚠️ LOW" : ""}
    </option>
  );
})
```

**New implementation steps:**

1. Replace the `<select id="pr-ingredient">` with the shadcn `<Combobox>` component.
2. Build the `options` array from `ingredients` + `branchInventory` using the same logic as above.
   - `value` = `i.id`
   - `label` = `i.name`
   - `keywords` = `[i.code, i.stockUnit]` (so users can search by code too)
3. Use `renderOption` to display the rich row:

   ```tsx
   renderOption={(opt) => (
     <div className="flex items-center justify-between w-full">
       <span>{opt.label}</span>
       <span className={opt.meta.isLow ? "text-destructive text-xs" : "text-muted-foreground text-xs"}>
         Stok: {opt.meta.stockQty} {opt.meta.moq > 1 && `(MOQ: ${opt.meta.moq})`}
         {opt.meta.isLow && " ⚠️ LOW"}
       </span>
     </div>
   )}
   ```

   > Note: `meta` is not in the base interface. Extend `ComboboxOption` locally or pass the extra data through `label` / `keywords`. A cleaner approach: make `ComboboxOption` accept a generic `meta?: Record<string, unknown>` or just let `renderOption` close over the ingredient data by using a `Map<id, ingredient>`.

4. Keep the same "add item" flow:
   - User picks ingredient from combobox → sets internal state `selectedIngredientId`
   - User types qty in the adjacent input
   - Clicks "+" button → adds to `prItems` array
   - Clear combobox selection after add (set value back to empty string)

5. **Important:** The combobox needs to manage its own open/close state. Use a local `const [ingredientOpen, setIngredientOpen] = useState(false)` or let the component handle it internally.

## 5. Edge Cases & Constraints

1. **FormData compatibility:** Native `<form>` + `FormData` is used in Waste, PR (to some extent), and Yield Tracking. The combobox is a React-controlled component, so it does not automatically participate in `FormData`. For each page:
   - If the form uses `FormData` + `fd.get("ingredientId")`, add a hidden `<input type="hidden" name="ingredientId" value={selectedId} />` alongside the combobox.
   - If the form uses React state (like PR's `prItems` array), no hidden input is needed; just wire `onChange` to state.

2. **Mobile UX:** The popover must not overflow the viewport. Ensure `max-h-72` and `overflow-y-auto` on the `CommandList`.

3. **Async data:** All ingredient lists are already fetched via `useQuery` / `Route.useLoaderData()` before the modal opens, so the combobox can be synchronous (no async loading state needed).

4. **Empty state:** When the search yields no results, show a friendly message in Indonesian: "Tidak ada bahan yang cocok".

5. **Selection clearing:** In the PR modal, after the user clicks "+" to add an item, the combobox must clear so they can pick the next ingredient. Ensure the component supports a controlled `value=""` state.

6. **No breaking changes to server functions:** This is purely a UI change. No server functions (`scm.ts`, `waste.ts`, etc.) should be modified.
