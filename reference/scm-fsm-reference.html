SCM Finite State Machine — Quick Reference

The redesigned PR→SJ→Invoice lifecycle as a formal FSM. Each transition is (current state → event → next state), owned by one actor.

State Diagram

[*] → Draft          (BA creates PR)
Draft → Pending          (BA submits)
Pending → UnderReview    (CA opens review)

UnderReview → Rejected                    (CA rejects)
UnderReview → InTransit                   (CA accepts + creates SJ)

InTransit → Delivered                      (CA marks dispatched)
Delivered → ReviewingSJ                    (BA opens receiving)
ReviewingSJ → WaitingForPayment            (BA confirms review)
WaitingForPayment → Finished               (CA marks "Telah Dibayar")

Rejected → [*]
Finished → [*]

Code Pattern: FSM Transition Table

const transitions = {
  Pending: {
    'open-review': {
      to: 'UnderReview',
      actor: ['admin_pusat', 'super_admin'],
    },
  },
  UnderReview: {
    reject: {
      to: 'Rejected',
      actor: ['admin_pusat', 'super_admin'],
      effects: ['writeRejectionReason'],
    },
    'accept-and-ship': {
      to: 'InTransit',
      actor: ['admin_pusat', 'super_admin'],
      effects: ['createSJ', 'createInTransit', 'deductSourceInventory'],
    },
  },
  // ... every state and event
}

async function transition(prId, event, user) {
  const pr = await getPR(prId)
  const rule = transitions[pr.status]?.[event]
  if (!rule)                           throw new FsmError('Cannot event from state')
  if (!rule.actor.includes(user.role)) throw new FsmError('Not authorized')
  for (const fx of (rule.effects ?? [])) await applyEffect(fx, pr, user)
  await updatePR(prId, { status: rule.to, lastEvent: event, updatedBy: user.id })
  await logAudit({ ... })
}
Key principle: One transition() function replaces all ad-hoc if (status === X && role === Y) checks. Build the FSM table first — UI and permissions follow automatically.
