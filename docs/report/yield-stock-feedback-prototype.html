Umpan Balik Stok — Tracking Produksi (/yield-tracking)

PROTOTIPE Sketsa kasar untuk direaksi — bukan implementasi. Berdasarkan ADR 0012: mencatat produksi langsung mengubah stok (bahan keluar −, bahan dihasilkan +), pembatalan membalik mutasi.

Data contoh: produksi kaldu ayam — Tulang Ayam 2000, Air 4000, Bawang Merah 200 → Kaldu Ayam (SFG) 4800. Satu baris sengaja dibuat negatif untuk menunjukkan peringatan.

Deep-link ke Kartu Stok? Halaman Kartu Stok ada di /inventory/ledger tetapi filter-nya hanya branchId/ingredientId/recipeId — belum ada filter reference, jadi tautan per-produksi tidak bisa langsung menunjuk barisnya. Opsi: (a) lewati tautan, cukup badge “stok dibalik” (tanpa perubahan server); (b) tambahkan filter reference ke getStockLedger + halaman ledger — tugas kecil lanjutan.

6

Keputusan data: dari mana pratinjau dapat stok saat ini?

Rekomendasi: pakai kembali getInventory — tidak perlu server function baru.
  • Query React Query ["branch-inventory", branchId] memanggil getInventory({ branchId, limit: 1000 }) saat modal dibuka / cabang diganti. Batas 1000 baris cukup untuk skala grup restoran ini.
  • Baris yang tidak ada di inventory (belum pernah distok di cabang) dianggap 0 — konsisten dengan semantik upsert-from-0 pada ADR 0012.
  • Untuk branch_admin (cabangnya sudah pasti), loader halaman bisa prefetch stok cabangnya agar pratinjau langsung tampil tanpa spinner.
  • Scoping tetap di server: getInventory mengunci branch_admin ke cabangnya sendiri.

Alternatif yang ditolak: menambah semua stok ke loader halaman (boros — ikut termuat walau modal tak dibuka); server function khusus getBranchInventoryMap (duplikasi query yang sudah ada).
