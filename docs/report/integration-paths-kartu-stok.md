# Integration Paths → Kartu Stok (stock_ledger)

> **Map:** [#114](https://github.com/admomoiyarisby/pos/issues/114) — "Integration paths → Kartu Stok + integration test suite"
> **Ticket:** [#115](https://github.com/admomoiyarisby/pos/issues/115) — Research: enumerate every inventory ↔ Kartu Stok write path
> **Generated:** 2026-05-14
> **Schema source:** `src/db/schema.ts` → `inventory` (branchId, ingredientId, quantity) and `stockLedger` (branchId, ingredientId?, recipeId?, type IN/OUT, quantity, balance, reference, notes). Kartu Stok UI reads via `getStockLedger` (src/lib/server/inventory.ts).

## How to read this matrix

| Column              | Meaning                                                   |
| ------------------- | --------------------------------------------------------- |
| #                   | Stable path id for test tickets                           |
| Source event        | User action / FSM transition that triggers the write      |
| Owner               | File + function                                           |
| Branch target       | Which branch's `inventory` is mutated                     |
| Ledger `type`       | IN (stock added) / OUT (stock removed)                    |
| `reference`         | Value written to `stockLedger.reference` (audit join key) |
| `balance` invariant | Must equal `inventory.quantity` after write               |
| Side ledgers        | Other tables mutated in same transaction                  |

`no-write` paths are explicitly listed as negative cases — they are in scope of the enumeration but must NOT produce ledger rows.

## 10 — Ledger branch vis (Kartu Stok read path)

`getStockLedger` (src/lib/server/inventory.ts) is **read-only**: filters by `branchId` / `ingredientId` / `recipeId`, plus Waste BOM scope (`wasteBomOnly` / `wasteBomRecipeId` via `wasteBomLedgerFilter` — ADR 0013, contract pinned by W4). When `stockLedger.recipeId IS NOT NULL`, Kartu Stok is showing finished-good movement (R1). When `ingredientId IS NOT NULL`, it is raw-ingredient movement (all others). `getInventory` similarly joins `ingredients` + `branches` for dashboard tiles; `reorder.ts` and `dashboard.ts` read inventory + ledger for anomaly/ROP — not write paths.

## Summary counts

- **POS:** 3 paths (P1 create, P2 void, P3 cancel-execute) — the last is same effect as P2 via different state machine.
- **Pengadaan FSM:** 8 effect paths (S1–S8) — 3 live ledger writers (S1, S3a, S6–S8), 1 pending-move (S2), 1 invoice-only (S3c/S4).
- **Mutasi FSM:** 8 effect paths (M1–M8) — mirror of Pengadaan but sender/receiver swapped; same guard (InsufficientStockError).
- **SO:** 2 inventory writers (O4 approve, O5 realize with Nasi sub-path) + 3 no-writes (O1 trigger, O2 submit, O3 investigation).
- **Supplier:** 3 inventory writers (D1 create, D2 update=2 ledgers, D3 delete).
- **Waste:** 1 direct writer (W1) + 2 FSM-triggered (S3b/M3b).
- **Recipe production:** 1 writer (R1) — the only writer of `stockLedger.recipeId`.
- **Yield tracking:** 2 writers (Y1 record mutation + Y1b cancel reversal) per ADR 0012.
- **Manual:** 2 writers (A1 batch, A2 destructive delete).
- **Total ledger-writing paths:** **≈ 22** distinct `stockLedger` insert patterns (excluding the legacy scm.ts 3-doc paths). Each needs at least one integration test asserting `stockLedger.balance == inventory.quantity` post-write, `type` correctness, and `reference` prefix.

## What the integration tests must prove (per-path checklist)

1. `inventory.quantity` after = `oldQty ± quantity` (or `physicalStock` for SO).
2. `stockLedger.type` is IN for additions, OUT for deductions (and flipped for voids/cancels).
3. `stockLedger.balance` equals post-write `inventory.quantity`.
4. `stockLedger.reference` equals the originating doc id (orderId, procurementId, transferId, `PROD-*`, `ADJ-*`, `SO:<id>`, `supplierDeliveryId`).
5. `stockLedger.branchId` equals the correct branch (Central vs dest vs sender vs receiver).
6. `inTransitInventory` / `pendingReviewInventory` side-effects are present/cleared as specified.
7. Error paths (InsufficientStockError, SO wrong date, AlreadyRealized, etc.) produce **no** ledger rows and leave inventory unchanged.
